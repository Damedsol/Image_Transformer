- **2026-09-17: Dev port-fallback fix — CORS loopback patterns + Vite strictPort (Fast Path, CICLO CERRADO, reviewer ✅)**
  - Symptom (user report): `pnpm dev` → `/api/convert` blocked with "No 'Access-Control-Allow-Origin' header is present" from origin `http://localhost:5174`, plus `[vite] failed to connect to websocket` to `ws://localhost:5173`.
  - Root cause: **port collision, not a dependency regression**. `ss -ltnp` showed :5173 held by an unrelated stale dev server (another project's Vite, pid alive since 2026-09-17) → this app's Vite fell back to :5174 and two hardcoded 5173 assumptions broke: (a) the dev CORS allowlist was the closed list `[...:3000, ...:5173, ...localhost]`; (b) `vite.config.ts` pinned `server.hmr.clientPort: 5173`, so the HMR socket targeted the *other* project's server.
  - Fix (R1/R2/R3): CORS resolution extracted to `backend/src/utils/corsOrigins.ts` (unit-testable without booting the HTTP server); dev returns anchored loopback patterns (`localhost`, `127.0.0.1`, `[::1]`, any port) while production keeps the exact-match list from `CORS_ORIGIN`/`CORS_ORIGINS` + `ALLOW_LOCALHOST` and still throws when empty; `vite.config.ts` gained `strictPort: true` and dropped `clientPort` so HMR follows the port the server actually owns.
