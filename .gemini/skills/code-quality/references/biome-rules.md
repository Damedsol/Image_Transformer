# Biome Code Quality Deep Dive for Gemini CLI

This reference document outlines complete rules, configuration schemas, and advanced edge cases for managing unified formatting and import organization using Biome in large-scale TypeScript monorepos.

## Quick Start (Single-Package)

A standard, lightweight `biome.json` configured at the root of a project:

```json
{
  "$schema": "https://biomejs.dev/schemas/1.8.0/schema.json",
  "organizeImports": {
    "enabled": true
  },
  "linter": {
    "enabled": false
  },
  "formatter": {
    "enabled": true,
    "formatWithErrors": true,
    "indentStyle": "space",
    "indentWidth": 2,
    "lineWidth": 100
  },
  "javascript": {
    "formatter": {
      "quoteStyle": "single",
      "semicolons": "always",
      "trailingCommas": "all"
    }
  }
}
```

## Standard Pattern (Monorepo Integration)

When using pnpm workspaces, configuration nesting can cause severe resolution performance drops and tool incompatibilities. Biome recommends centralizing configurations.

### Root `biome.json` Schema with Multi-Environment Globals

```json
{
  "$schema": "https://biomejs.dev/schemas/1.8.0/schema.json",
  "organizeImports": {
    "enabled": true
  },
  "linter": {
    "enabled": false
  },
  "formatter": {
    "enabled": true,
    "formatWithErrors": true,
    "indentStyle": "space",
    "indentWidth": 2,
    "lineWidth": 100,
    "ignore": [
      "**/node_modules/**",
      "**/dist/**",
      "**/build/**",
      "**/.next/**",
      "pnpm-lock.yaml"
    ]
  },
  "javascript": {
    "globals": [
      "console",
      "process",
      "Express",
      "NodeJS",
      "setTimeout",
      "clearTimeout",
      "setInterval",
      "clearInterval"
    ],
    "formatter": {
      "quoteStyle": "double",
      "trailingCommas": "all",
      "semicolons": "always",
      "arrowParentheses": "always"
    }
  }
}
```

## Advanced & Edge Cases

### 1. Resilient Formatting under Syntax Errors

During rapid development or refactoring, a developer may save a file containing syntax errors. Traditional formatters (like Prettier) will completely crash, blocking the developer workflow and breaking pre-commit hooks.
Setting `"formatWithErrors": true` allows Biome's parser to isolate syntax errors locally, formatting the syntactically valid portions of the file while leaving the error tokens untouched.

### 2. Integration with pre-commit CLI (`lint-staged`)

When lint-staged feeds changed files to Biome, some files might not match any rules or might be explicitly ignored. By default, Biome will throw an error:
`Error: No files matched the given patterns.`
This breaks the commit process. The solution is to use the `--no-errors-on-unmatched` flag.

**Correct Pre-commit Config (`.lintstagedrc`):**
```json
{
  "*": "biome format --write --no-errors-on-unmatched"
}
```

### 3. Handling Overlapping Toolchains

If a dependency requires an older ESLint rule, or if VSCode keeps falling back to the legacy Prettier extension, you must disable formatting capabilities inside other IDE configurations.

**VSCode Workspace Settings (`.vscode/settings.json`):**
```json
{
  "editor.defaultFormatter": "biome.biome",
  "editor.formatOnSave": true,
  "editor.codeActionsOnSave": {
    "source.organizeImports.biome": "always",
    "source.fixAll.biome": "always"
  }
}
```

## Common Mistakes & Antipatrones ("The Do Not List")

- **DO NOT** create a separate `biome.json` inside a subfolder (e.g., `backend/biome.json`) inside a monorepo. This forces the Biome LSP to spin up multiple parallel processes, causing heavy CPU overhead and conflicting formatting outputs.
- **DO NOT** run `biome format` without ignoring `pnpm-lock.yaml` or huge autogenerated JSON logs. Always declare an explicit `ignore` array in the formatter settings.
- **DO NOT** combine Biome formatting with Prettier inside the same project. Remove Prettier packages entirely to ensure one single formatting engine exists.
